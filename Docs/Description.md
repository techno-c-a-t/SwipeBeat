# ПОЛНОЕ ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)
## Разработка Android-приложения для сортировки музыки «Slidebox Music»

---

## 1. Введение и технологический стек
Приложение предназначено для быстрой сортировки локальных аудиофайлов на Android-устройствах с помощью вертикальных свайпов (вверх — одобрить, вниз — пропустить). Результатом работы является автоматически сгенерированный плейлист в формате `.m3u` или `.m3u8`, готовый к импорту в сторонние плееры (например, AIMP).

*   **Язык программирования:** Kotlin.
*   **Минимум SDK:** API 21 (Android 5.0).
*   **Целевой SDK:** API 33+ (Android 13+).
*   **Архитектурный паттерн:** MVVM (Model-View-ViewModel) [1].
*   **Интерфейс:** Классическая разметка (XML Views) + ViewBinding [1]. *Использование Jetpack Compose запрещено из-за несовместимости с императивным подходом.*
*   **Аудиоплеер:** Jetpack Media3 (ExoPlayer).
*   **Навигация:** Single Activity с переключением экранов через переключатель видимости (`View.GONE`/`VISIBLE`) или транзакции фрагментов.

---

## 2. Архитектура приложения (MVVM)

### Слой Model (Данные)
*   **`Track` (Data class):**
    *   `id: String`, `title: String`, `artist: String`, `album: String`, `filePath: String` (абсолютный путь для плейлиста), `uri: Uri` (для воспроизведения), `durationMs: Long`.
*   **`PlaylistRepository`:**
    *   Интерфейс для работы с файлами. Должен абстрагировать работу с памятью: на версиях < Android 10 работает через прямые пути (`java.io.File`), на Android 10+ — через Storage Access Framework (SAF) и `DocumentFile`.
*   **`PlaylistParser`:**
    *   Отвечает за парсинг существующих плейлистов `.m3u`/`.m3u8` и генерацию новых.
*   **`LocalDirectoryScanner`:**
    *   Сканирует выбранные папки и возвращает список файлов.
*   **`AudioPlayerEngine`:**
    *   Обертка над Media3 ExoPlayer. Реализует методы: `play`, `pause`, `seekTo`, `setSpeed`, `setVolume`.

### Слой ViewModel (Бизнес-логика)
*   **`SortingViewModel`:**
    *   Управляет очередью сортировки (`trackQueue`), списками `approvedTracks` и `rejectedTracks`.
    *   Хранит индекс текущего трека и состояние плеера (играет/пауза).
    *   Оповещает View через реактивные потоки (`StateFlow` или `LiveData`).

### Слой View (Интерфейс)
*   **`MainActivity`:**
    *   Управляет видимостью экранов, инициализирует ViewBinding, слушает жесты, перехватывает системную кнопку «Назад» для отображения диалога выхода и сохранения.

## 3. Спецификация экранов и UI-элементов

### Экран 1: Экран подготовки (Стартовый)
Экран должен быть максимально свободным от визуального шума.

*   **Элементы UI:**
    1.  **Шапка:** Название приложения по центру. Справа — кнопка-шестеренка (открывает Экран 4: Настройки).
    2.  **Карточка-кнопка «Выбрать источники»:** Отображает количество выбранных папок/плейлистов.
    3.  **Оверлей «Менеджер источников» (Bottom Sheet / Dialog):** Открывается при тапе на карточку источников. Содержит:
        *   Кнопку «Добавить папку» (по умолчанию предлагает быстро отсканировать директорию `Downloads/Slidebox`).
        *   Кнопку «Импортировать плейлист» (вызов системного проводника для выбора `.m3u`/`.m3u8`).
        *   Список «Недавно использованные папки» (хранится в SharedPreferences).
    4.  **Селектор логики объединения** (Отображается, только если выбрано $>1$ источника): Три кнопки-иконки: *Объединить все без дубликатов*, *Оставить только дубликаты*, *Оставить только уникальные*.
    5.  **Панель сохранения:** Автоматическое имя файла плейлиста `Sorted_[Дата_Время]`. Возможность изменить папку сохранения через проводник.
    6.  **Кнопки запуска:** Крупная «Начать новую сортировку» и «Продолжить прошлую сессию» (если в БД есть незаконченный прогресс).

---

### Экран 2: Рабочий экран сортировки
*Экран сфокусирован на одной задаче. Все лишнее скрыто.*

*   **Элементы UI:**
    1.  **Центральная CardView трека:** Крупная обложка (встроенная в теги или заглушка), крупное название песни, имя артиста.
    2.  **Плеер (Скрытый по умолчанию):** 
        *   *Логика появления:* Тап по верхней грани экрана показывает тонкую полосу прогресса (Seekbar) и счетчик `Текущий/Всего` на 3 секунды, затем они плавно затухают (`alpha` анимация).
    3.  **Кнопка «Два списка» (в углу):** Открывает Экран 3 (Шторка истории).
*   **Логика управления и жесты:**
    *   **Тап по карточке:** Мгновенный Play/Pause. Поверх обложки на 0.5 сек всплывает индикатор статуса (иконка паузы или воспроизведения).
    *   **Долгий тап на карточку:** Всплывающее оверлей-окно с техническими данными: путь к файлу, формат, битрейт, частота дискретизации.
    *   **Свайп ВВЕРХ $\to$ Одобрить:** Карточка улетает вверх. Запускается короткая тактильная вибрация (Haptic Feedback) [2]. Трек заносится в `approvedTracks`.
    *   **Свайп ВНИЗ $\to$ Отклонить:** Карточка улетает вниз. Запускается двойная короткая тактильная вибрация [2]. Трек заносится в `rejectedTracks`.
*   **Системный Back-прессинг:** При нажатии кнопки «Назад» телефона всплывает диалог подтверждения: *«Прервать сортировку? Текущий прогресс сохранен»* (кнопки «Выйти» / «Остаться»).

---

### Экран 3: Списки решений (Шторка истории)
Реализуется в виде выезжающей снизу шторки (`BottomSheetDialogFragment`).

*   **Структура:**
    *   Две горизонтальные вкладки сверху: **[ Одобренные (X) ]** и **[ Отклоненные (Y) ]**, где X и Y обновляются на лету. Переключение между вкладками — свайпом влево/вправо или тапом.
*   **Элементы списка и интерактивность:**
    *   **Тап по строке трека:** Запускает его фоновое воспроизведение (превью), не закрывая шторку.
    *   **Свайп трека ВЛЕВО:** Переносит трек в противоположную группу (из Одобренных в Отклоненные и наоборот).
    *   **Свайп трека ВПРАВО:** Сбрасывает решение. Трек удаляется из списков и возвращается на самый верх очереди сортировки (при закрытии шторки он станет следующим активным треком на Экране 2).

---

### Экран 4: Экран настроек
Открывается поверх Экрана 1 при нажатии на шестеренку.

*   **Разделы и элементы:**
    1.  **Категория «Умный старт» (Smart Jump):**
        *   Переключатель (Switch) «Быстрый старт (Пропуск интро)».
        *   Ползунок (SeekBar) выбора секунд старта (от 0 до 60 сек).
        *   Ползунок (SeekBar) выбора процентов старта (от 0% до 50%).
        *   *Логика:* Плеер должен автоматически перематывать трек на указанную позицию при запуске. Если длительность трека меньше порога — воспроизведение начинается с 0 секунды.
    2.  **Категория «Медиатека»:**
        *   Статус разрешения доступа к памяти. Кнопка «Запросить доступ», если разрешения отозваны.
        *   Список «Черный список папок» с возможностью добавлять/удалять пути (чтобы исключить системные звуки из сканирования).
    3.  **Категория «Интерфейс»:**
        *   Ползунок «Сила вибрации» (влияет на интенсивность тактильного отклика при свайпах).
        *   Выбор темы: Светлая / Темная / AMOLED (чистый черный цвет фона для OLED экранов).
        *   Ползунок «Масштаб карточки» (динамически изменяет `layoutParams` ширины и высоты `CardView` на Экране 2).
        *   Переключатель «Автостарт воспроизведения» (если выключен, при свайпе следующий трек загружается на паузе).

## 4. Спецификация ключевых алгоритмов

### Алгоритм автоопределения формата (M3U vs M3U8)
При экспорте плейлиста приложение не заставляет пользователя выбирать формат вручную:
1.  Скрипт проверяет все строки путей и метаданных результирующего списка на наличие не-ASCII символов (например, кириллицы).
2.  Если найден хотя бы один не-ASCII символ $\to$ файл кодируется в UTF-8 и записывается с расширением `.m3u8`.
3.  Если все символы укладываются в диапазон ASCII $\to$ файл записывается в стандартной кодировке с расширением `.m3u`.

### Алгоритм тактильной вибрации (Haptic Feedback)
*   Для старых версий Android (ниже API 26) использовать классический `Vibrator.vibrate(milliseconds)`.
*   Для новых версий (API 26+) использовать `VibrationEffect.createOneShot` для одиночного отклика и `VibrationEffect.createWaveform` для двойного.
*   Амплитуда вибрации должна масштабироваться в зависимости от значения ползунка «Сила вибрации» из настроек.

Используй этот чек-лист, чтобы выявить, какие модули проекта отсутствуют или требуют доработки:

*   [ ] **Архитектурный каркас:** Настроен ли ViewBinding, используется ли паттерн MVVM с одной активностью (`MainActivity`)?
*   [ ] **Разрешения Android:** Реализован ли корректный запрос разрешений на чтение памяти для версий до Android 13 (`READ_EXTERNAL_STORAGE`) и для Android 13+ (`READ_MEDIA_AUDIO`)?
*   [ ] **Менеджер источников (Экран 1):** Сверстано ли диалоговое окно источников, работает ли сканирование папки `Downloads/Slidebox` и реальный парсинг файлов `.m3u8`?
*   [ ] **Рабочий экран (Экран 2):** Реализованы ли вертикальные свайпы карточки (Вверх = Одобрить, Вниз = Отклонить), работает ли тап по карточке как Play/Pause, скрываются ли элементы плеера по таймеру?
*   [ ] **Тактильный отклик:** Работает ли разная вибрация для свайпа вверх и свайпа вниз?
*   [ ] **Плеер (Media3):** Интегрирован ли ExoPlayer, работает ли бесшовное переключение треков при свайпах?
*   [ ] **Шторка истории (Экран 3):** Сверстана ли двухвкладочная шторка, наполняется ли она реальными действиями, работают ли свайпы строк истории для изменения решений?
*   [ ] **Настройки (Экран 4):** Сверстан ли экран настроек, работают ли ползунки масштаба карточки и силы вибрации?
*   [ ] **Логика «Умного старта»:** Реализован ли пропуск интро в плеере на основе настроенных секунд или процентов?
*   [ ] **Алгоритм записи плейлиста:** Реализовано ли автоопределение M3U/M3U8 на основе кодировки символов при сохранении результатов сессии?
*   [ ] **Сохранение состояния:** Сохраняется ли прогресс сортировки в локальную базу данных (например, Room или облегченный JSON/SharedPreferences) при выходе из приложения или при закрытии экрана?
